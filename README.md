# BlockBoard — образовательный портал по блокчейну

**BlockBoard** — веб-платформа для курса «Блокчейн-технологии в экономике и финансах». Содержит конспекты лекций, глоссарий, интерактивные демонстрации блокчейна и AI-чатбота с системой учебных токенов.

🔗 **Живое демо:** https://blockboard.vercel.app/

## Управление лекциями

Все лекции хранятся как обычные Markdown-файлы в папке `content/lectures/`. Никакой базы данных нет — достаточно добавить или удалить файл.

### Как добавить лекцию

1. Создайте файл в папке `content/lectures/` с именем по шаблону:

   ```
   Конспект_Лекция_N_НазваниеЛекции.md
   ```

   Где `N` — номер лекции (определяет порядок в каталоге). Например:
   ```
   Конспект_Лекция_7_DeFi.md
   ```

2. Заполните файл по структуре ниже. Система автоматически распознаёт секции по эмодзи-заголовкам:

```markdown
# Название лекции
*Курс: ...*

---

## ⚡ Лекция за 30 секунд

- Ключевой тезис 1
- Ключевой тезис 2
- Ключевой тезис 3

---

## 📖 Лекция за 10 минут

### 1. Раздел первый

Текст раздела...

### 2. Раздел второй

Текст раздела...

---

## 📚 Полный конспект

### 1. Раздел первый

**Суть:** ...

**Как это работает / Механизм:**
...

> 💡 **Пример из лекции:** ...

---

## 🔑 Ключевые термины

- **Термин** — определение
- **Термин** — определение

---

## ✅ Итог

Заключительный текст лекции...
```

**Важно:** система распознаёт секции по ключевым словам в заголовке:
- Секция «30 секунд» — заголовок должен содержать `⚡` или `30 секунд`
- Секция «10 минут» — `📖` или `10 минут`
- Полный конспект — `📚` или слово `Полный`
- Термины — `🔑` или слово `термин`
- Итог — `✅` или слово `итог`

3. После добавления файла **передеплойте на Vercel** (или перезапустите локальный сервер). Лекция появится в каталоге автоматически — кода менять не нужно.

### Как удалить лекцию

Просто удалите соответствующий `.md` файл из `content/lectures/`. Лекция исчезнет из каталога и из базы знаний чатбота.

### Как изменить содержимое лекции

Откройте `.md` файл и отредактируйте текст. Нумерация лекций определяется только именем файла (`Лекция_N_`), не содержимым.

## Управление глоссарием

Словарь терминов хранится в файле `content/glossary.json`.

### Формат записи

```json
[
  {
    "term": "Блокчейн",
    "definition": "Распределённая децентрализованная база данных, в которой транзакции между участниками фиксируются без центрального регулятора",
    "lecture": 2
  }
]
```

Поле `"lecture"` — номер лекции, к которой относится термин (используется для фильтрации в интерфейсе). Значение `0` означает «общий термин».

### Как добавить термин

Добавьте новый объект в массив в `glossary.json`:

```json
{
  "term": "Новый термин",
  "definition": "Определение термина",
  "lecture": 7
}
```

Термины в интерфейсе сортируются по алфавиту автоматически.

## Система квизов и токенов

### Как студент получает токен

Студент может получить токен двумя способами через чатбот (`/bot`):

**Способ 1 — Квиз**
1. Студент пишет в чат что-то вроде «сделай квиз по лекции 3»
2. Чатбот генерирует 7 вопросов с вариантами ответов по теме лекции
3. Студент отвечает на вопросы прямо в чате
4. При результате **6/7 или выше** — чатбот автоматически выдаёт токен
5. Токен появляется в «кошельке» студента (кнопка в правом нижнем углу чатбота)

**Способ 2 — Объяснение концепции**
1. Студент пишет «объясни мне X» или просит чатбота проверить его понимание темы
2. После диалога, если чатбот оценивает понимание как достаточное, он выдаёт токен

### Формат токена

Токен выглядит так:
```
HK1:eyJ...подпись...
```

Это HMAC-SHA256 подпись — подделать без знания секретного ключа сервера невозможно.

### Как преподаватель проверяет токен

**Через веб-интерфейс:**
1. Зайти на страницу `/verify` (или `https://blockboard.vercel.app/verify`)
2. Вставить токен студента в поле и нажать «Проверить»
3. Система покажет: валиден ли токен, когда выдан, за что выдан

**Через прямую ссылку:**
```
https://ваш-домен.vercel.app/api/verify?coin=HK1:...токен...
```

Ответ придёт в формате JSON:
```json
{ "valid": true, "issued": "2025-04-15T10:32:00Z", "reason": "quiz_pass" }
```

**Проверка не требует базы данных** — вся информация закодирована в самом токене и верифицируется криптографически.

## Деплой и настройка

### Необходимые API-ключи

Для работы чатбота нужны ключи от двух бесплатных сервисов:

| Сервис | Для чего | Бесплатный лимит | Где получить |
|---|---|---|---|
| Google Gemini | Основной AI | ~1 500 запросов/день | https://aistudio.google.com/app/apikey |
| Groq | Резервный AI (если Gemini недоступен) | 14 400 запросов/день | https://console.groq.com/keys |

Достаточно одного ключа (Gemini), Groq — запасной.

### Деплой на Vercel (рекомендуется)

1. **Форкните или клонируйте репозиторий** на свой GitHub-аккаунт

2. **Зайдите на [vercel.com](https://vercel.com)** и войдите через GitHub

3. **Нажмите "Add New Project"** → выберите репозиторий BlockBoard

4. **Перед деплоем добавьте переменные окружения** (раздел "Environment Variables"):

   | Переменная | Значение |
   |---|---|
   | `GEMINI_API_KEY` | Ваш ключ от Google AI Studio |
   | `GROQ_API_KEY` | Ваш ключ от Groq (необязательно) |
   | `HODL_SECRET` | Любая длинная случайная строка |

   > ⚠️ **`HODL_SECRET` важен:** этот секрет используется для подписи токенов студентов. Если его изменить — все ранее выданные токены станут невалидными. Установите один раз и не меняйте.

5. **Нажмите "Deploy"** — Vercel сам соберёт и опубликует сайт

6. Сайт будет доступен по адресу вида `https://ваш-проект.vercel.app`

### Запуск локально

```bash
# 1. Установить зависимости
npm install

# 2. Создать файл с ключами
cp .env.example .env.local
# Открыть .env.local и вставить свои ключи

# 3. Запустить сервер разработки
npm run dev
# Сайт будет на http://localhost:3000
```

## Структура проекта

```
blockboard/
├── content/
│   ├── lectures/          ← Лекции в формате Markdown (сюда добавлять новые)
│   └── glossary.json      ← Словарь терминов (сюда добавлять термины)
├── src/
│   ├── app/               ← Страницы сайта (Next.js App Router)
│   │   ├── api/
│   │   │   ├── chat/      ← API чатбота (Gemini + Groq)
│   │   │   ├── mint/      ← API выдачи токенов
│   │   │   └── verify/    ← API верификации токенов
│   │   ├── lectures/      ← Каталог и страницы лекций
│   │   ├── bot/           ← Страница чатбота
│   │   ├── glossary/      ← Страница глоссария
│   │   └── verify/        ← Страница верификации токенов
│   ├── components/        ← React-компоненты
│   └── lib/
│       ├── lectures.ts    ← Загрузка и парсинг лекций
│       ├── rag.ts         ← RAG: поиск по лекциям для чатбота
│       ├── search.ts      ← Поиск по ключевым словам
│       └── tokens.ts      ← Генерация и верификация токенов
├── .env.example           ← Шаблон переменных окружения
└── docs/
    └── PRD.md             ← Полное техническое задание проекта
```

**Технологии:** Next.js 14, TypeScript, Tailwind CSS, Framer Motion, Google Gemini API, Groq API.

**Хранение данных:** база данных отсутствует — лекции читаются из файлов, токены верифицируются криптографически без сохранения на сервере.
